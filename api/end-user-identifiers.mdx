---
title: "End-user identifiers"
description: "Name the person on your side a request is for, using an opaque ID instead of personal data."
---

## Why send it

`end_user_id` is a stable, opaque ID of **your own** end user — the person in your product the request is for. If our safety systems flag content, it tells us which of your users a flagged request came from, so we can act on that user instead of your whole account.

## What to send

- Send the same value for the same person every time.
- Use your own database ID, or a hash of it.

<Warning>
  Never send personal data: no email addresses, phone numbers, names, IP addresses, or anything else that identifies a person directly.
</Warning>

## Rules

| Rule | Detail |
|------|--------|
| Type | String |
| Length | 1–256 characters, after trimming surrounding whitespace |
| Characters | No control characters |
| Invalid values | The request fails with `400` and a message naming `end_user_id` |
| Empty string | Treated as absent |

The field is optional today, but we strongly recommend sending it on every request.

## Where it is accepted

Send it as a top-level field next to `model`/`input` or `inputs`, **not inside `input`**:

- `POST /v1/prediction`
- `POST /v1/workflows/trigger/{workflowID}/{versionID}`
- `POST /v1/workflows/bulk-trigger/{workflowID}/{versionID}` — applies to every run in the batch
- `POST /v1/public/@{nickname}/workflows/{slug}/versions/{versionID}/trigger`, and the variant without `@{nickname}`

In a workflow, every step of the run carries the same `end_user_id`.

## How we use and keep it

We store it with the run. It never changes billing, routing, the model's input, the output, webhooks, or rate limits. It is deleted together with the run's inputs and outputs under your retention settings, except where we must preserve a record by law.

Where the law requires us to report illegal content, we refer to the user by your ID.

## Example

<CodeGroup>
```bash cURL
curl -X POST https://api.eachlabs.ai/v1/prediction \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "flux-1-1-pro",
    "end_user_id": "user_8f14e45fceea",
    "input": {
      "prompt": "A beautiful sunset over the ocean"
    }
  }'
```

```python Python
import requests

response = requests.post(
    "https://api.eachlabs.ai/v1/prediction",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "flux-1-1-pro",
        "end_user_id": "user_8f14e45fceea",
        "input": {"prompt": "A beautiful sunset over the ocean"}
    }
)
```

```javascript JavaScript
const response = await fetch("https://api.eachlabs.ai/v1/prediction", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": "Bearer YOUR_API_KEY",
  },
  body: JSON.stringify({
    model: "flux-1-1-pro",
    end_user_id: "user_8f14e45fceea",
    input: { prompt: "A beautiful sunset over the ocean" },
  }),
});
```
