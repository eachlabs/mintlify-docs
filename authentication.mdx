## API Key Authentication

All each::labs APIs authenticate requests with your API key sent as a Bearer token in the `Authorization` header.

```bash
curl https://api.eachlabs.ai/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Getting Your API Key

1. Sign in to [eachlabs.ai](https://eachlabs.ai)
2. Navigate to **Settings** > **API Keys**
3. Click **Create API Key**
4. Copy and store your key securely

<Warning>
  Your API key grants full access to your account. Never expose it in client-side code, public repositories, or logs.
</Warning>

## Using the API Key

Include the `Authorization: Bearer YOUR_API_KEY` header in every request:

<CodeGroup>
```bash cURL
curl https://api.eachlabs.ai/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```python Python
import requests

headers = {"Authorization": "Bearer YOUR_API_KEY"}
response = requests.get("https://api.eachlabs.ai/v1/models", headers=headers)
```

```javascript JavaScript
const response = await fetch("https://api.eachlabs.ai/v1/models", {
  headers: { "Authorization": "Bearer YOUR_API_KEY" },
});
```
</CodeGroup>

## Authentication per Product

| Product | Header | Base URL |
|-|-|-|
| each::api | `Authorization: Bearer YOUR_API_KEY` | `https://api.eachlabs.ai` |
| each::workflows | `Authorization: Bearer YOUR_API_KEY` | `https://api.eachlabs.ai` |
| each::sense | `Authorization: Bearer YOUR_API_KEY` | `https://eachsense-agent.core.eachlabs.run` |

<Note>
  Workflow endpoints with no `api.eachlabs.ai` equivalent (get/update workflow, versions, categories, public workflows) are served from `https://workflows.eachlabs.run/api/v1`, a fully supported host that uses the same Bearer authentication. One exception: public workflow triggers take your key as `api_key` in the JSON request body — see [Public Workflows](/workflows/endpoints/public-workflows).
</Note>

<Note>
  Some endpoints like `GET /v1/models` (listing models) do not require authentication. Check individual endpoint documentation for details.
</Note>

## Authentication Errors

If your API key is missing or invalid, you'll receive a `401` response:

```json
{
  "error": "Invalid or missing API key"
}
```

### Common Causes

| Issue | Solution |
|-|-|
| Missing header | Add `Authorization: Bearer YOUR_API_KEY` to your request headers |
| Invalid key | Verify the key in your dashboard |
| Expired key | Generate a new API key |
| Wrong product URL | Ensure you're using the correct base URL for the product |

## Security Best Practices

- Store API keys in environment variables, never in source code
- Use different keys for development and production
- Rotate keys periodically
- Revoke compromised keys immediately from your dashboard
