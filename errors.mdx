## Error Response Format

Errors returned directly by an API request use this format:

```json
{
  "error": "Human-readable error message"
}
```

This is different from a prediction that was accepted and later failed while
running. In that case, the polling request still succeeds, the prediction has
`status: "error"`, and the failure detail is in `output`:

```json
{
  "status": "error",
  "output": {
    "error_code": "PROVIDER_RATE_LIMIT",
    "error_message": "This model is temporarily rate limited. Retry shortly."
  }
}
```

Use `output.error_code` for program logic. `output.error_message` is
customer-readable guidance and its wording may improve over time; do not parse
it or depend on provider names or provider-specific messages.

## HTTP Status Codes

| Status | Meaning | Description |
|--------|---------|-------------|
| `400` | Bad Request | Invalid request parameters or body |
| `401` | Unauthorized | Missing or invalid API key |
| `403` | Forbidden | Operation not allowed (e.g., locked resource) |
| `404` | Not Found | Resource does not exist |
| `429` | Too Many Requests | Rate limit exceeded |
| `500` | Internal Server Error | Unexpected server error |

## Common Errors

### 400: Bad Request

```json
{
  "error": "slug parameter is required"
}
```

**Causes:**
- Missing required parameters
- Invalid parameter types or values
- Malformed JSON body
- Input validation failure

### 401: Unauthorized

```json
{
  "error": "Invalid or missing API key"
}
```

**Causes:**
- `Authorization: Bearer YOUR_API_KEY` header not included
- API key is invalid or expired

### 403: Forbidden

```json
{
  "error": "Workflow is locked and cannot be modified"
}
```

**Causes:**
- Attempting to modify a locked workflow or version
- Insufficient permissions for the requested operation

### 404: Not Found

```json
{
  "error": "Failed to fetch model: model not found"
}
```

**Causes:**
- Invalid model slug
- Non-existent prediction ID, workflow ID, or execution ID
- Resource was deleted

### 429: Rate Limited

```json
{
  "error": "Rate limit exceeded. Please retry after 60 seconds."
}
```

**Handling:**
- Implement exponential backoff
- Check the `Retry-After` header when available
- Consider reducing request frequency

### 500: Internal Server Error

```json
{
  "error": "Failed to fetch models: internal error"
}
```

**Handling:**
- Retry with exponential backoff
- If persistent, contact support

## Product-Specific Errors

### each::api: Prediction Errors

Errors that prevent a request from being accepted use the HTTP error format
above. Predictions that fail after being accepted use these common
`output.error_code` values:

| Error code | Meaning | Recommended handling |
|------------|---------|----------------------|
| `INPUT_VALIDATION_ERROR` | Input does not match the model schema | Correct the input before retrying |
| `INPUT_DOWNLOAD_ERROR` | An input file could not be downloaded | Use a publicly accessible URL before retrying |
| `PROVIDER_BAD_REQUEST` | The model rejected the input as invalid | Review the model's input requirements |
| `PROVIDER_REJECTED` | The request could not be processed, including content-safety rejection | Adjust the input before retrying |
| `PROVIDER_RATE_LIMIT` | The model is temporarily rate limited | Retry with backoff |
| `PROVIDER_SERVER_ERROR` | The model service is temporarily unavailable | Retry with backoff |
| `NETWORK_ERROR` | The model service could not be reached | Retry with backoff |
| `PROVIDER_FAILED` | The model did not produce an output | Adjust the input or retry |
| `EXECUTION_TIMEOUT` | The execution exceeded its time limit | Retry, or reduce the input size if it persists |
| `PIPELINE_CONFIG_ERROR` | An internal model configuration error occurred | Retry later; contact support if it persists |
| `PUBLISH_FAILED` | The completed result could not be published | Retry; contact support if it persists |
| `WORKER_LOST` | The execution worker stopped unexpectedly | Retry |
| `ITERATION_ERROR` | One or more iterations in a partial execution failed | Inspect the iteration errors and decide whether to retry the failed work |

Some legacy or unclassified failures can still return a string or an object
without `error_code`. Do not infer a code by parsing that text. Log the
prediction ID and contact support if the failure persists.

### each::workflows: Execution Errors

| Error | Description |
|-------|-------------|
| `"Workflow not found"` | Invalid workflow ID or slug |
| `"Version not found"` | Invalid version ID |
| `"Workflow is locked"` | Attempting to modify a locked workflow |
| `"ExecutionFailed"` | A workflow step failed during execution |
| `"invalid input: missing required field"` | Trigger input doesn't match workflow input schema |

### each::sense: Agent Errors

| Error | Description |
|-------|-------------|
| `"Session not found"` | Invalid session ID |
| `"Model execution failed"` | Underlying model execution error |
| `"Workflow execution timeout"` | Execution exceeded 15-minute limit |

## Retry Strategy

We recommend exponential backoff for transient errors (429, 500). Here's how to set that up:

<CodeGroup>
```python Python
import time
import requests

def request_with_retry(url, headers, json=None, max_retries=3):
    for attempt in range(max_retries):
        response = requests.post(url, headers=headers, json=json)
        if response.status_code in (429, 500):
            wait = 2 ** attempt
            time.sleep(wait)
            continue
        return response
    return response
```

```javascript JavaScript
async function requestWithRetry(url, options, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch(url, options);
    if ([429, 500].includes(response.status)) {
      await new Promise((r) => setTimeout(r, 2 ** attempt * 1000));
      continue;
    }
    return response;
  }
  return response;
}
```
