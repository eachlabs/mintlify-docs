This page is for people using Claude in the browser, in the Claude desktop app, on a phone, or in Claude Code. Codex, Cursor and other clients are covered on the [MCP Server](/mcp#clients) page. ChatGPT, the Codex app, Grok and Mistral Le Chat are under [Works in other MCP apps](/mcp#works-in-other-mcp-apps).

## What you get

The each::labs plugin bundles two things:

| Part | What it is |
| --- | --- |
| Connector | The hosted each::labs MCP server at `https://mcp.eachlabs.ai/mcp`, which lets Claude use each::labs tools: the model catalog, `run_model`, the workflow tools, the video tools and the cards. The [MCP Server](/mcp#tools) page lists them. |
| Skills | Twelve recipes Claude follows for common media tasks: which model fits, which inputs it takes, which tool to call. See [Skills](#skills). |

A **card** is a small interactive panel that Claude shows inside the conversation: you upload a file on it, adjust a model's settings, pick one of several results, or choose a range on a timeline. When you press a card's button, Claude continues on its own; there is nothing to type. Cards show in Claude on the web, in the desktop app and in the mobile apps. The cards are [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview) served by the each::labs MCP server, not by the plugin, so other MCP apps such as ChatGPT show them too. Claude Code and other terminals show no cards: Claude asks in the chat instead, and results come back as text.

You can also add the connector on its own without the plugin; see [Connector without the plugin](#connector-without-the-plugin). Either way the sign-in and the tools are the same.

## What you can ask

Ask in your own words. Claude chooses the model, builds its input and runs it. Each job is billed to the each::labs organization you chose at [sign-in](#first-sign-in).

### Generate images and pick one

> Give me four variants of a fantasy trading card with a fire dragon. I want to pick one.

The results arrive together on one card. Select the one you like, as often as you like; the button under them then reads **Use variant 2**, or the number you selected. Press it and Claude continues with that image. The choice is final. One request makes up to 8 variants.

### Turn a dozen screenshots into one slideshow

> Make a slideshow video from my 12 app screenshots, 3 seconds each.

One upload card takes the whole set. Drop all twelve at once; they upload four at a time, each with a thumbnail and a progress bar. When every file is up, Claude picks them up and returns the video on a result card with a player and a download button.

### Make music, then trim it

> Compose a 30-second upbeat lo-fi intro.

The track comes back with a player and one download button per format. Then:

> Cut it down to the part I like.

Claude shows the track on a timeline with two handles. Drag them, press **Preview** to listen, and press **Use this range**. When you give exact seconds instead, such as "keep 0:05 to 0:20", Claude trims without a card.

### Make a video from a photo

> Turn this photo into a 5-second clip where the camera slowly pushes in.

Claude asks for the photo on an upload card, runs a video model and shows the clip on a result card that plays in the conversation. A video often takes 5 to 10 minutes; Claude shows it as still running and checks again until it is done. See [When a tool says running](#when-a-tool-says-running).

### Adjust the settings before a run

> Restyle this portrait as a Monet oil painting. Let me adjust the settings first.

Claude shows the model's settings as a form: the prompt, size, number of images, seed and any other option the model takes. Change what you want and press **Run**. After the first run of a model in a conversation, Claude ends its reply with a short **Adjust generation settings** line naming a few of that model's settings; ask to change any of them and the form appears.

### Run your organization's workflow

> Which workflows do we have? Run our product clip workflow with this tote bag photo.

Claude lists the [workflows](/workflows/overview) your organization built in the dashboard. When a workflow needs inputs you have not given, Claude shows them as a form, with a file picker for each photo, video or audio input. Press **Run**; the outputs show together as a gallery.

### Cut or crop a video

> Crop this video to 9:16 for a story.

Claude shows the first frame with a rectangle. Move and resize it, or lock it to 1:1, 16:9, 9:16 or 4:5, and press **Use this crop**. To cut a clip, ask "keep the best three seconds" and use the timeline the same way as for audio. Exact numbers, such as "cut the first 10 seconds", skip the card.

## Add the plugin

Pick the tab for where you use Claude. On a Team or Enterprise plan, read [Team and Enterprise plans](#team-and-enterprise-plans) first: an Owner may already have added the plugin for you.

<Tabs>
  <Tab title="claude.ai and Claude Desktop">
    Plugins are on the Pro, Max, Team and Enterprise plans. The steps are the same in the browser and in the desktop app's chat. **Customize** is the page that holds your connectors, skills and plugins.

    <Steps>
      <Step title="Open Customize > Plugins">
        Go to **Customize > Plugins**.
      </Step>
      <Step title="Upload the plugin">
        Select **Add > Upload plugin** and choose the plugin zip file from each::labs.
      </Step>
      <Step title="Add the plugin">
        Open the **each::labs** plugin and select **Add** if it is not added yet.
      </Step>
      <Step title="Connect the bundled connector">
        Adding a plugin does not sign you in to anything. Open the plugin's **Connectors** tab. If the `eachlabs` connector shows **Not added**, add it from this tab; then select **Connect**. The each::labs consent page opens; see [First sign-in](#first-sign-in).
      </Step>
    </Steps>

    The plugin's skills load whether or not you connect. A skill cannot reach each::labs until the connector shows **Connected**. Once added, the connector also appears under **Customize > Connectors**.

    | To | Do this |
    | --- | --- |
    | Turn the plugin off or on | Open it from **Customize > Plugins** and use its **Disable plugin** toggle |
    | Get an update | A plugin added from a zip does not update by itself. Upload the newer zip the same way |
    | Remove it | Open the plugin, open its menu and select **Remove**. The connector stays under **Customize > Connectors** until you remove it there |
    | Use it on a phone | Add it on the web or in the desktop app. Plugins are saved to your account, so the mobile apps have it too |

    Anthropic describes these steps under [Plugins](https://claude.com/docs/plugins/overview).
  </Tab>
  <Tab title="Claude Code">
    Unzip the plugin zip file from each::labs into a folder, then add that folder and install the plugin from a Claude Code session:

    ```text

    /plugin install eachlabs@eachlabs
    ```

    Replace `./eachlabs-plugin` with the path of the folder you unzipped.

    Choose a scope when asked; **Install for you (user scope)** gives you the plugin in every project. Then run `/mcp`, select `eachlabs` and sign in when prompted; see [First sign-in](#first-sign-in).

    From your shell, the same install is:

    ```bash
    claude plugin marketplace add ./eachlabs-plugin
    claude plugin install eachlabs@eachlabs
    ```

    | To | Do this |
    | --- | --- |
    | Turn the plugin off or on | Run `/plugin`, open the **Installed** tab and press **Space** on the plugin. From your shell: `claude plugin disable eachlabs@eachlabs` and `claude plugin enable eachlabs@eachlabs` |
    | Get an update | Unzip the newer zip into the same folder, then run `claude plugin marketplace update eachlabs` and `claude plugin update eachlabs@eachlabs` |
    | Remove it | `claude plugin uninstall eachlabs@eachlabs` |
    | Use the plugin from claude.ai instead | A plugin added under **Customize > Plugins** also syncs to Claude Code when you sign in with the same account, as `eachlabs@synced`. Run `/reload-plugins` or start Claude Code again to load it |

    Anthropic describes these commands under [Install and manage plugins](https://code.claude.com/docs/en/plugins/install).
  </Tab>
</Tabs>

### Restarts and updates

| Client | After you add the plugin | After a new version |
| --- | --- | --- |
| claude.ai, Claude Desktop, mobile | Ready in your conversations, with no restart | Stays on its version until you upload a newer zip. The new version is then ready with no restart |
| Claude Code | The install message says whether it is active now. If it says `Run /reload-plugins to apply.`, Claude Code reloads for you | The running session keeps its version and shows `Plugin updated: eachlabs · Run /reload-plugins to apply`. Run `/reload-plugins`, or the next session loads it |

Changes to the cards come from the each::labs server, not from the plugin. A card always shows its current version, with no update or restart on your side.

## Connector without the plugin

Add the server URL as a custom connector. You get the same tools and the same sign-in, without the skills: you describe the task and Claude chooses the tools itself.

<Steps>
  <Step title="Open Customize > Connectors">
    Go to **Customize > Connectors**.
  </Step>
  <Step title="Add a custom connector">
    Click **Add custom connector**.
  </Step>
  <Step title="Enter the server URL">
    Enter `https://mcp.eachlabs.ai/mcp`. Leave the OAuth client ID and secret empty; each::labs sets them up for you.
  </Step>
  <Step title="Add and connect">
    Click **Add**, then **Connect**. The each::labs consent page opens; see [First sign-in](#first-sign-in).
  </Step>
</Steps>

On the Free plan you can add one custom connector. In Claude Code, the connector alone is one command; see [Claude Code](#claude-code).

Each member's each::labs account must belong to the each::labs organization that should pay for the runs, and the member picks that organization at sign-in. A member who signs in with a personal account and organization is billed there instead.

## First sign-in

Connecting opens the each::labs consent page in a new browser tab.

1. If you are not signed in to the each::labs dashboard, the page sends you through [sign-in](https://www.eachlabs.ai/sign-in) and back to the consent page.
2. Choose the **Organization**. The page states: *Predictions will run and bill as &lt;organization&gt;*. Every job you run from Claude is charged to this organization at the same prices as the API.
3. Review the permissions listed (the [scopes](/mcp#scopes)) and click **Approve**.

Claude stores the resulting token and refreshes it in the background; you do not sign in again. The token never appears in the conversation. To bill a different organization, disconnect the connector under **Customize > Connectors** and connect again.

If the page fails with *organization has no runner credential*, open the [dashboard](https://www.eachlabs.ai) once as that organization, then connect again.

### Tool approvals

Before running a tool that creates something (a model run, a workflow run, a file upload), Claude asks you to allow it. **Always allow** remembers the answer for that tool. Tools that only read (checking a job, listing models or workflows) run without a prompt. The first time a card appears, Claude also asks whether to show the each::labs app; allow it.

You can turn the connector off for one conversation: click the **+** button in the chat and select **Connectors**, then turn each connector on or off for that conversation.

## Give a file as input

Most recipes start from your own photo, video or audio file. Tool inputs are URLs, and a file attached with Claude's paperclip stays inside Claude: it cannot reach a connector tool. When a model needs a file, Claude shows the each::labs **upload card** instead. Put the file on the card, not on the paperclip.

```mermaid
flowchart LR
  C["Claude shows the upload card and waits"] --> P["You drop files on the card or pick them"]
  P --> U["The card uploads them from your browser to each::labs storage"]
  U --> W["Claude receives the files' URLs"]
  W --> R["Claude runs the model"]
```

| Step | What happens |
| --- | --- |
| 1 | You ask for the result you want: "turn this photo into a short clip". |
| 2 | Claude shows the upload card and waits for your files. |
| 3 | Drop the files on the card, or pick them with its button, such as **Choose a photo**. On a phone the button opens the photo library. |
| 4 | The card uploads each file from your browser to each::labs storage and shows a thumbnail and progress. Nothing passes through Claude. |
| 5 | When the card has every file it asked for, it hands them to Claude by itself. If you upload fewer than it takes, press **Done, send to the chat**. |
| 6 | Claude receives the files' URLs and runs the model. |

<Frame caption="An upload card waiting for two photos">
  <img style={{ maxWidth: "440px", width: "100%" }} src="/images/mcp/01a-upload-empty.webp" alt="each::labs Upload photos card asking for the portrait and the outfit photo, with the text Drop up to 2 photos here and a Choose photos button." />
</Frame>

If Claude does not pick the upload up on its own, the card shows **Send to the chat by message**. It writes the file list into your message box; press **Send** and Claude continues. Claude shows its standard caution notice above a message an app prepared.

| Limit | Value |
| --- | --- |
| File kinds | Image, video or audio, as the recipe asks for |
| Files per card | One card takes a whole set: up to 50 files, or fewer when the chosen model accepts fewer. A card for one specific file, such as the face to use, takes exactly one |
| File size | 100 MB per file |
| Upload | Four files upload at a time; the rest wait their turn. Choosing more files than the card takes, or a file over 100 MB, is refused before anything uploads |
| Time to pick | Claude waits for the card up to 60 seconds at a time. After each wait it reads any new message from you, then waits again. If it stops waiting before you are done, tell Claude when the upload is finished |
| Storage | The file is kept for 180 days, or for your organization's own retention period, as with [Upload file](/storage/upload-file). Anyone who has the file's link can open it; links are long random addresses that are not listed anywhere |
| Already have a URL | Paste a public URL in the message instead; no card is needed |
| Claude Code | Does not show cards. Claude asks in the chat for a public link to the file instead; see [Claude Code](#claude-code) |

## Cards in the conversation

Besides the upload card, these cards appear. [What you can ask](#what-you-can-ask) shows each one.

| You see | When |
| --- | --- |
| The result: the image, a video or audio player, and download buttons | Every run that produces media. A file in several formats has one button per format. A workflow's outputs show together as a gallery |
| Several results to choose from | You asked for several variants of one prompt, up to 8 in one request. Select one as often as you like, then press the button under them, which reads **Use variant** and the number you selected. Claude continues with that one, and the choice is final |
| A form with the model's settings and a **Run** button | You ask to adjust settings, or a run has options worth choosing first |
| A **Compare** button under an edited image or video | The result is an edit of a file you gave. Drag the handle to compare before and after |
| A timeline with two handles, or a rectangle on the first frame | You want to cut a clip or crop a frame and have not given exact numbers. Press **Use this range** or **Use this crop**. Trimmed audio keeps its format; FLAC comes back as mp4 |
| A workflow's inputs as a form, with a file picker for each photo, video or audio input | A workflow needs inputs you have not given |

A card that cannot load in your app says so and tells you what to give in the chat instead, such as a public file link or the start and end times.

A card you already used stays locked on your choice when you come back to the conversation later. To see a result again, ask Claude to show it; it shows the file on a card without running anything.

## Skills

Claude loads a skill when your request matches its description. To pick one yourself, type `/` in the message box and choose it.

| Skill | Use it for |
| --- | --- |
| `eachlabs-image-generation` | New images from a text prompt: Flux, GPT Image, Gemini, Imagen, Seedream and other model families |
| `eachlabs-image-edit` | Editing an existing image: style transfer, background removal, upscaling, inpainting, virtual try-on, 3D, analysis |
| `eachlabs-video-generation` | New videos from text, images or reference inputs: transitions, motion control, talking head, avatars |
| `eachlabs-video-edit` | Editing an existing video: lip sync, translation, subtitles, audio merge, style transfer, extension |
| `eachlabs-music` | Songs, instrumentals, lyrics and podcasts; song extension, stem separation, song recognition |
| `eachlabs-voice-audio` | Text to speech, transcription with speaker labels, voice conversion |
| `eachlabs-face-swap` | Swapping faces between images |
| `eachlabs-fashion-ai` | Fashion model imagery, virtual try-on, runway videos, campaign visuals |
| `eachlabs-product-visuals` | Product photography and videos for e-commerce: product shots, background replacement, lifestyle scenes, 360-degree views |
| `eachlabs-workflows` | Running a workflow your organization built and reading its executions |
| `gpt-image-v2` | OpenAI GPT Image v2 for text to image and instruction-based edits |
| `bytedance-seedance-2-0` | ByteDance Seedance 2.0 for video with native audio, from text or from an image |

The public [eachlabs/skills](https://github.com/eachlabs/skills) collection also has skills that run through each::sense, the each::labs agent. Access to each::sense is limited to specific organizations, so the plugin does not include those skills. Most of their tasks, such as background removal, upscaling or trimming, work through the skills and tools above.

## When a tool says running

A tool waits about 20 seconds for its job. A job that takes longer, such as a long video or a multi-step workflow, shows as still running, and Claude checks again until the job is done, then shows the result. The job keeps running on each::labs the whole time. You do not need to ask; if Claude stops before the job is done, ask "is that job done?" and it checks again.

When you asked for several variants, Claude checks on all of them together, and they arrive on one card with the picker once every variant is done.

If a reply is cut off before Claude got the job's id, Claude can list your organization's recent runs and pick the job up from there instead of starting it again. That list shows only each run's id, model, status, time and result link.

Long videos can take 5 to 10 minutes. Claude keeps checking until yours is ready, and asks you before trying a different model, so you are never charged for a run you did not ask for.

You are billed once, when the job runs, not for checking. Details are under [Long jobs](/mcp#long-jobs).

Results are URLs to files on each::labs storage, kept as long as [uploads](#give-a-file-as-input). Download anything you want to keep longer. A data result, such as a transcript or an analysis, comes back as text without a card.

## Claude Code

The plugin installs as the **Claude Code** tab under [Add the plugin](#add-the-plugin) shows. To add only the connector, without the skills:

```bash
claude mcp add --transport http eachlabs https://mcp.eachlabs.ai/mcp
```

Run `/mcp` inside Claude Code, select `eachlabs`, and sign in when prompted. The tools appear once the sign-in completes.

| Difference from Claude in the browser | What to do |
| --- | --- |
| Cards do not show | Claude asks in the chat for what a card would collect: a public link to the file, the start and end times, the crop area, the settings or your choice of variant. Results come back as text with their URLs |
| A plugin update waits for a reload | Run `/reload-plugins`, or start Claude Code again |

## Remove it

| What | Where |
| --- | --- |
| The plugin in claude.ai or Claude Desktop | **Customize > Plugins**, open the plugin, open its menu, select **Remove** |
| The connector | **Customize > Connectors**, open the connector's menu, select **Remove**. A Team or Enterprise Owner removes the organization's copy under **Organization settings > Connectors** |
| The plugin in Claude Code | `claude plugin uninstall eachlabs@eachlabs` |
| The connector in Claude Code | `claude mcp remove eachlabs` |

Removing the plugin keeps the connector, and removing the connector keeps the plugin's skills. Remove both to remove everything.
