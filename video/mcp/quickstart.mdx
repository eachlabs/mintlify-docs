## What you get

An MCP server that exposes the Video API as native agent tools — 37 of the 44 capabilities in the [capabilities reference](/video/capabilities) today, with client-side schema validation, automatic submit-and-poll, and results returned as artifact URLs or structured analysis JSON. Your agent edits video by calling tools; billing and auth ride your eachlabs account — an OAuth login on the hosted endpoint, or your API key locally. The remaining capabilities (`audio_analysis`, `audio_duck`, `audio_master`, `crossfade`, `silence_split`, `sticker_overlay`, `title_card`) are reachable through the [HTTP API](/video/quickstart) and will be wrapped as tools in a later release.

## Connect your agent

There are two ways to connect:

- **Hosted (recommended):** point your client at `https://mcp.eachlabs.ai/mcp` and approve access in the browser. Nothing to install, no API key to manage; jobs bill to the organization you approve on the consent page.
- **Local (stdio):** run the server yourself with `npx` and your API key; jobs bill to the key's account.

The examples register the hosted server as `eachlabs-video` and the local one as `video` — distinct on purpose, so both can coexist. Hosted setup is available for Claude Code and Codex today; Claude Desktop, Cursor, and Kimi Code connect via the local server.

<Tabs>
  <Tab title="Claude Code">
    Hosted:

    ```bash
    claude mcp add --transport http eachlabs-video https://mcp.eachlabs.ai/mcp
    ```

    Then run `/mcp` inside Claude Code and log in when prompted.

    Local:

    ```bash
    claude mcp add video --env EACHLABS_API_KEY=YOUR_API_KEY -- npx -y @eachlabs/video-api-mcp
    ```
  </Tab>
  <Tab title="Codex">
    Hosted:

    ```bash
    codex mcp add eachlabs-video --url https://mcp.eachlabs.ai/mcp --oauth-resource https://mcp.eachlabs.ai/mcp
    ```

    The `add` command opens the OAuth flow in your browser. Re-authenticate later with the same scopes the server requires:

    ```bash
    codex mcp login eachlabs-video --scopes predictions:create,predictions:read
    ```

    Local — add to `~/.codex/config.toml`:

    ```toml
    [mcp_servers.video]
    command = "npx"
    args = ["-y", "@eachlabs/video-api-mcp"]
    env = { EACHLABS_API_KEY = "YOUR_API_KEY" }
    ```

## Use it

Ask your agent to do video work with any publicly downloadable media URL — inputs are staged automatically (see [Quickstart — inputs](/video/quickstart#2-provide-your-input-video)); `s3://` URIs from onboarding also work:

> "Trim the first 12 seconds of `YOUR_INPUT_URL`, burn the captions from this SRT, and give me the result URL."

The agent chains the `trim` and `captions` tools; each tool call returns the hosted artifact URL (or JSON for the [analysis capabilities](/video/capabilities#response-shapes)) plus the billed cost.

## Tool inventory

One tool per wrapped capability — same names and parameters as the [capabilities reference](/video/capabilities) (the `keep_ranges`/`silence_remove` pair is exposed under its original wire name, `silence_remove`) — plus `run_ffmpeg` (raw ffmpeg for beta organizations; contract and safety boundary in [run_ffmpeg](/video/capabilities#run_ffmpeg)) and `get_job` for checking a long-running job later. Parameters are validated client-side before submit, and server-side again (`additionalProperties: false`), so a malformed tool call never bills.

## Notes for agent builders

- Long jobs: the server polls with backoff; if a job outlives the polling budget the tool returns the prediction ID and your agent resumes with `get_job`.
- Billing semantics are identical to the REST surface: [Billing & Limits](/video/billing-limits).
