## What is each::storage?

each::storage is managed file hosting for the media that flows through each::labs. Upload an image, video, or audio file once and get back a stable public URL you can pass straight into [each::api](/api/overview) predictions and [each::workflows](/workflows/overview) — no need to stand up your own bucket or CDN.

It's also the layer each::labs uses to deliver results: model and workflow outputs are typically (though not always) served as `cdn-us.eachlabs.ai` URLs, so the files you upload and the results you get back share one fast, consistent host.

## Why use it

- **No infrastructure to run** — skip hosting and signing your own uploads; we hand you a presigned URL and a stable public link.
- **Built for model inputs** — returned URLs are reliably fetchable by our executors, so predictions don't fail on inaccessible media.
- **One platform, one key** — uploads use the same `Authorization: Bearer` API key as the rest of each::api.
- **Fast delivery** — files are served from a CDN over HTTPS.

## How it works

<Steps>
  <Step title="Request a presigned URL">
    Call [Upload File](/storage/upload-file) (`POST /v1/upload/presign`) with the file's content type. You get a short-lived upload URL plus a public `public_url`.
  </Step>
  <Step title="Upload the bytes">
    `PUT` the raw file to the presigned URL. A `200 OK` means it's live.
  </Step>
  <Step title="Use the URL">
    Pass `public_url` as an input to any model or workflow. Call [Delete File](/storage/delete-file) when you no longer need it.
  </Step>
</Steps>

## How long files are kept

Every file stored through [Upload File](/storage/upload-file) has one **effective retention**, decided when the presign request is created. Three inputs can set it. The first one that applies wins:

| Priority | Source | Effect |
|----------|--------|--------|
| 1 | **Saved organization policy** — [Organization settings → Storage file retention](https://www.eachlabs.ai/organization-settings), set by an organization owner | A custom duration (up to 365 days) or **Never expires**. Overrides `expires_in_seconds` in both directions. |
| 2 | **`expires_in_seconds` on the upload request** | `60`–`31536000` seconds, or **`-1` for no expiry**. Used only when no organization policy is saved. |
| 3 | **Platform default** | **180 days**. Used when there is no saved policy and the request omits `expires_in_seconds`. |

That means an organization policy of 1 minute turns a request with `-1` into a 1-minute file, and a policy of **Never expires** turns any finite `expires_in_seconds` into a file with no expiry. Only the **saved** policy counts — a value chosen in the settings page but not yet confirmed has no effect. The full decision table, including the `0` and out-of-range cases, is in [Upload File](/storage/upload-file#how-the-expiry-is-decided).

- **No expiry** means no *automatic retention deletion*. It is not a guarantee that the file stays available forever: you can still remove it with [Delete File](/storage/delete-file), and the deadline starts when the presign request is created, not when the `PUT` finishes.
- **Future files only.** Changing the policy never extends or shortens files that already exist.
- **Check the result.** The presign response carries `expires_at` when the file has a deadline and omits it when it has none. Read it before assuming a request got no expiry.

### Where this applies

The rules above cover files stored through the each::storage upload pipeline: files you upload with [Upload File](/storage/upload-file), and generated outputs hosted through that same pipeline (the organization policy governs them; a per-request `expires_in_seconds` does not, because there is no such field on a prediction). Two things are *not* covered automatically:

- Some paths use their own expiry. For example, video compression output uses a separate default and ignores the organization policy.
- Files that stay on an external or provider URL rather than a `cdn-us.eachlabs.ai` storage URL are not stored by each::storage, so these settings do not apply to them.

### Storage file retention vs. execution data retention

Organization settings has two separate retention settings. Neither one overrides the other.

| Setting | Controls | Does not control |
|---------|----------|------------------|
| **Storage file retention** | How long the media **files** (uploaded inputs and generated outputs in each::storage) are kept | The execution record |
| **Execution inputs and outputs** | How long the **record** of an execution is kept: submitted prompts, parameters, input references and returned response data | The underlying media files |

Keeping an execution record keeps the *URL* in its response, not the file behind it. If the file has expired, the URL no longer works even though the record still lists it. To keep both, set both policies.

## Browse & filter your files

Every file you upload or that a model generates shows up on the [storage page](https://www.eachlabs.ai/storage) in your dashboard. Filter by **model**, file type, source (uploaded inputs vs. generated outputs), execution, or date range to find exactly what you need.

## Limits

| Limit | Value |
|-------|-------|
| Max file size | 100 MB per upload |
| Presigned URL lifetime | 15 minutes |
| Stored file retention | 180 days (default). A saved [organization policy](https://www.eachlabs.ai/organization-settings) takes precedence; otherwise set per upload with `expires_in_seconds` (60 seconds to 365 days, or `-1` for no expiry). See [How long files are kept](#how-long-files-are-kept) |
| Supported file types | `image`, `video`, `audio`, `other` |

## Where your data resides

Files are stored in the **United States** and delivered through the `cdn-us.eachlabs.ai` CDN over HTTPS.

## Access & privacy

Each `public_url` contains an unguessable identifier but is readable by anyone who has the link — treat it as public. File management is scoped to your organization through your API key: you can only delete files uploaded under your own account.
